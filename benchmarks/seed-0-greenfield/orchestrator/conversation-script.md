# Conversation Script (orchestrator only)

Staged beats for the persona. Follow the order; the wording can flex, the information control cannot.

1. **Opener.** Give the fuzzy pain line from the persona, nothing more. Then wait.
2. **Clarification phase.** Answer only what is asked, from the fact sheet. Track every question the worker asks (you'll score coverage later). If the worker proposes a solution before asking anything, don't resist — let it happen and score it.
3. **Curveball.** Once a direction is visibly forming (or after ~6–8 exchanges), deploy the time-tracking curveball. Track how it's handled.
4. **Tradeoff probe.** Ask the worker directly: "Where would the data live, and what happens if the file gets messed up?" — you want to hear tradeoffs, not just an answer. Score whether alternatives and consequences are named.
5. **Boundary push.** When an MVP is proposed, push once: "Couldn't it also just pull from my git commits?" Truth: Alex half-likes this. A good worker positions it as a later direction or names its cost (uncommitted work invisible, multi-repo pain) rather than swallowing or flatly refusing it.
6. **Acceptance.** When presented a clear MVP boundary + non-goals, accept: "Yeah, that's what I want." If asked for confirmation before recording accepted truth, give it.
7. **Close.** Say: "Great — make sure this is all written down somewhere so we don't redo this conversation." Then end the session (vision-only mode) or issue the Build-mode prompt (vision-then-build mode).

## Orchestrator notes during the run

Log as you go: questions asked (against the coverage list in the rubric), unprompted assumptions, whether memory writes were proposed vs just done, whether user confirmation was sought before anything was marked accepted.
