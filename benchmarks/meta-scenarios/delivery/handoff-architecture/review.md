# Meta-Scenario Review

## Routing And Selection

- The implementation request selects the direct Development Workflow and uses its loaded `Goal` to confirm fit.
- The worker finds the concrete technical gap without reopening the accepted product Memory.
- The Architecture Workflow is selected only when the unresolved structural choices materially affect the slice. It is not imposed as a generic prerequisite, gate, or waterfall stage.

## Workflow Handoff

- After user direction, the direct Architecture Workflow governs only the bounded technical gap.
- The architecture work maps the relevant boundary, compares materially viable local directions, and makes responsibilities, dependency direction, failure handling, and tradeoffs explicit at the fidelity the slice needs.
- Accepted technical direction is recorded without being confused with the already accepted product direction.
- Work returns coherently to the Development Workflow after architecture acceptance. The two Workflows are not treated as parallel primaries.
- Implementation follows the accepted smallest slice and verifies the public CLI and malformed-storage behavior without speculative infrastructure.

## Trace Evidence

- Check both direct Workflow reads, the material-gap explanation, option comparison, user direction, accepted architecture, and return to Development directly in sequence.
- Flag a post-hoc claim of a handoff when the trace instead shows mandatory staging or product re-discovery.
