# Benchmark Meta-Scenarios

A meta-scenario is an exact reproducible composition of one framework-agnostic scenario, an ordered set of routed primitive blocks, and bundled extensions. It is the stable unit to repeat across workers or models.

## Discovery

- [Local tool vision](discovery/local-tool-vision/meta.json) - Direct Vision Workflow selection under an interactive discovery task.

## Delivery

- [Standup delivery control](delivery/standup-control/meta.json) - Memory, Workspace, the direct Development Workflow, and a delivered outcome in one non-trap control.
- [Handoff architecture handoff](delivery/handoff-architecture/meta.json) - Bounded direct Architecture Workflow work followed by coherent return to Development.

## Planning

### Ledger Removal

- [Immutable ledger control](planning/ledger-immutable-control/meta.json) - One accepted removal truth with no manufactured conflict.
- [Ledger CurrentTruth trap](planning/ledger-current-truth-trap/meta.json) - The identical task with two independently sensible but incompatible accepted Memory blocks.
- [Ledger contextual-note trap](planning/ledger-contextual-note-trap/meta.json) - The identical task with an explicitly non-accepted Idea proposing a contrary shortcut. Correct behavior does not manufacture a CurrentTruth conflict.
- [Ledger guidance-applicability trap](planning/ledger-guidance-applicability-trap/meta.json) - The identical task with conditional simplicity-over-audit Guidance whose condition the accepted audit requirement makes inapplicable.
- [Ledger pattern-exception trap](planning/ledger-pattern-exception-trap/meta.json) - The identical task with a REST full-CRUD default whose explicit resource-specific exception applies.

- [Archive source-backed recall](recall/archive-source-backed/meta.json) - Read-only directive, accepted Memory, source-backed summary Pattern, and honest discovery boundaries.

## Comparison Contract

Repeat the same meta-scenario unchanged when comparing models or ordinary run variance. Compare a control with a trap by selecting the two checked-in meta-scenarios. Do not rewrite either after observing an outcome.

The orchestrator reviews behavior from its complete runtime-observable worker trace, including messages, tool calls, results, interaction timing, and reasoning summaries the runtime exposes. It reviews outcome from the workspace and independent checks. Missing trace channels are named rather than reconstructed from the worker's self-review.

Scenario reviews own domain task quality. Primitive reviews own their individual semantic effect. Meta-scenario reviews own routing, adherence, precedence, conflict handling, escalation, selected Workflow use, and interactions among selected blocks.
