# Workflows

## Essence

Workflows defines what `{forgePath}/workflows/_workflows.md` and `{forgePath}/workflows/` should do in the installed framework.

Workflows describe action sequences. They say what to do next.

## Use When

- Work needs a repeatable sequence.
- Designing, implementing, testing, reviewing, documenting, or handing off.
- The sequence is useful across more than one task.

## Do Not Use When

- The content is a placement rule.
- The content is static project context.
- The content is long-lived active truth better suited to a directive or guide.

## Default Rules

- Keep workflows scoped enough for an agent to follow without loading half the workspace.
- Put task and work-package behavior inside workflows unless repeated use proves a separate folder is needed.
- Workflows may reference patterns, templates, directives, and guides.
- A workflow should name expected evidence when the work needs proof.
- A workflow says what to do next. A pattern says where and how things live.

## Useful Notes

Start with fewer workflows. Add them when repeated work proves the shape.
