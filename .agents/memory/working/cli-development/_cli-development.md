# CLI Development

This route retains unfinished work and the context needed to resume it. The [Plan](plan.md) selects the next boundary, [Project Control](project-control.md) owns the queue and permanent identities, and each Task defines its scope and evidence. The [wave capsule](one-zero-polish-wave.md) retains shared frozen decisions.

Completed Tasks, earlier execution checkpoints and superseded analyses are in [Archived CLI Development](../../archived/cli-development/_cli-development.md). Open questions remain in the candidate queue and the Emerging [Memory authority analysis](../../emerging/analysis/cli-design-retrospective/memory-authority-boundary.md). Historical analyses supply provenance rather than another execution plan.

## Axioms

- Read the compact Plan, Project Control and selected Task before implementation.
- A Task defines current scope, decisions, implementation discoveries and acceptance state. A subtask narrows that scope.
- Keep candidates contextual and validate historical evidence before relying on it.
- Keep this route small and current. Completed work belongs in Archived Memory.
