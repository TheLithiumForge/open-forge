# Accept The Mutation Foundation

## Task State

- State: Planned after every mutation-foundation behavior Task.
- Responsible role: Mastermind.
- Parent: [Mutation Foundation](_mutation-foundation.md).

## Acceptance Review

Inspect contracts, source, tests, and direct consumers. Confirm shared primitives
contain no route, Extension, install, update, repair, or cleanup policy. Confirm no
universal mutation plan, DI container, fake filesystem, shell command, hidden
rollback, legacy lifecycle recognition, or unlocked workspace effect.

## Executable Evidence

Run complete managed projects and published AOT Integration evidence for lock
contention, lifecycle schema, revalidation race, atomic create/replace/delete,
verification mismatch, cancellation boundaries, Git results, and recovery states.
Audit owned temporary artifacts and unchanged unrelated bytes after every failure.

## Pass Condition

- Every primitive has direct evidence and typed failure states.
- Lock ownership and post-lock revalidation precede every workspace effect.
- Lifecycle and recovery source generation passes with reflection disabled.
- Platform-specific differences are explicit and within accepted contracts.
- Status/Doctor/Repair/Cleanup can later read facts without depending on command
  implementations.

Update parent, Plan, and Checkpoint in the accepted integration commit. Only then
may route or lifecycle mutation command Tasks begin.

## Failure Routing

Return contract defects to Contracts, lock/schema defects to Lock/Lifecycle,
effect defects to Apply, Git/recovery defects to Recovery/Git, and unprovable
platform safety to Architecture.
