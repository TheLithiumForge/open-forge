# Freeze Route-List Models And Evidence

## Task State

- State: Complete.
- Implementer: Mastermind.
- Responsible role: Mastermind.
- Parent: [Route Discovery](../_route-discovery.md).
- Contracts: [Interface](../../../../../crystallized/documents/cli/contracts/route/list/interface.md) and [Behavior](../../../../../crystallized/documents/cli/contracts/route/list/behavior.md).

## Expected Outcome

Every route-list guarantee maps to one production owner and required evidence.
The command-local definitions, binding, request, result, findings, selection, row,
coverage, and next-action contracts are frozen before behavior delegation.

## Command Root Model

Create at `Core/Commands/Route/List/`:

- `RouteListDefinitions`: `route`, `list`, `source-reference`, depth option, depth
  values, command identity, and finding codes.
- A future `RouteListHelpSections` under `List/Shared/Rendering/` in the
  Presentation Task owns examples, related commands, and help product sections.
  Those sections do not belong to `RouteListDefinitions`.
- `RouteListBinding`: closes `RouteListRequest` and `RouteListResult` through the
  accepted Shell binding. It contains symbol construction and request binding,
  not operation logic.
- `RouteListRequest`: selected workspace, optional source reference, requested
  depth, and presentation-independent operation facts.
- `RouteListSelection`: attempted identity and resolved identity are distinct.
- `RouteListResult`: schema version, concrete command identity, status, workspace,
  selection, requested/effective depth, rows, findings, coverage, and next action.
- `RouteListRow`, `RouteListFinding`, and `RouteListCoverage`: immutable
  command-local data shapes with state-specific factories where fields vary.
- `RouteListOperation`: coordinator call surface only; implementation follows
  child Tasks.

Support folders remain absent until their behavior Task creates at least two
cohesive files.

### Serialization Boundary

Foundation owns the generic reflection-disabled source-generation boundary. The
later Presentation Task owns concrete projection DTOs under
`List/Shared/Rendering/` and registers them in `Shell/Serialization`. The internal
`RouteListResult` is the domain result; it is not itself the wire DTO.

## Evidence Matrix

Map every Interface and Behavior heading to:

- production owner;
- Unit evidence;
- Integration evidence;
- EndToEnd evidence;
- Native AOT evidence;
- preserved test candidate or missing case; and
- current state: contract only, covered, proof gap, or not applicable.

Port no test in this Task. Move relevant preserved cases into a Task-local
disposition table with keep, rewrite, split, merge, or remove and the contract
reason. The returning-link-chain case is mandatory Integration evidence.

### Contract Resolution Notes

- A syntactically valid, marker-bounded Loader `Entries` region with zero direct
  route declarations is a completely inspected empty root set and may produce
  `complete` with zero rows. Missing markers, malformed declarations, or an
  unreadable Loader make coverage incomplete or blocked as the direct cause
  requires. The preserved empty-body expectation is rewritten accordingly.
- Repeated physical identity is not automatically a cycle. Foundation active
  identity tracking distinguishes a link target repeated on the active resolution
  stack from a finite sequential contained alias; external and dangling identities
  remain separate outcomes. Preserved alias-equals-cycle expectations are removed.
  Evidence must cover these cases as distinct outcomes.
- Result `next` is one shared `CliNextAction { command, reason }`; `complete`
  forbids it; `attention` may carry it; and `incomplete`, `invalid`, `blocked`,
  `failed`, and `interrupted` require it.
