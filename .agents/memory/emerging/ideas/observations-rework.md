# Observations Rework

Direction sketched 2026-07-08. Observations stay in the framework as a potential top self-growth mechanism, but the current shape does not match how agents actually behave.

- Dogfood evidence: observations were the least reliable primitive; agents missed the closeout write even with confirmed direct exposure to the exact instruction.
- Not every chat should produce an observation, just as not every discussion produces a decision.
- Distributed work makes local-only recurrence thresholds ineffective: many agents can independently encounter the same problem once without any agent seeing the repetition.
- Record one concrete occurrence when it is plausibly reusable, surprising, or costly enough that losing it would impede later comparison. Keep its evidence, source, scope, and uncertainty visible.
- Before creating a parallel observation, search for an existing one and add the new occurrence or relationship there when it has the same subject and meaning.
- Repeated independent occurrences justify consolidation and a promotion proposal, for example into a pattern or directive, so future agents stop rediscovering the same lesson.
- Explicit user statements that an idea should be preserved or explored belong directly in the matching emerging idea route; they do not need to masquerade as observations.
- Needs: a cheap write and search path, distributed recurrence framing, bounded usefulness language that encourages capture without converting raw activity into memory, and honest wording that the write is agent self-enforced.
- Related: load closeout material early per the loading-reliability decision, since early exposure measurably improved closeout compliance in dogfood v4.
