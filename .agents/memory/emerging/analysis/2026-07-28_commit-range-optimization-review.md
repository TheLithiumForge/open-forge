# Commit Range Optimization Review

## Question

Does an independent optimization reviewer find material maintenance improvements that semantic-loss and writing-quality reviews do not?

## Method

A fresh read-only agent reviewed `HEAD~3..HEAD`, covering the committed Memory wording, overwrite migration, and Layers migration. It received the commit range, directly related current sources, and a bounded optimization prompt. It did not receive the uncommitted reference-propagation report and did not edit files.

The reviewer looked for repeated current meaning, mixed responsibilities, parallel answers to one question, unnecessary files or links, baseline cost, and disproportionate validation. It was instructed to preserve useful local summaries at independent entry boundaries and to distinguish current contracts from rationale and history.

## Distinct Findings

### Recursive Scope

The [route scope contract](../../crystallized/documents/framework/routing/scope.md) is authoritative for the complete recursive placement rule. Memory architecture, the installed Memory entrypoint, Memory Maintenance, a Writing Standard example, and phrase-level tests also carry parts of the same answer.

The installed Memory entrypoint needs a compact operational axiom because it is an independent runtime boundary. Memory architecture needs the state-and-scope consequence. The other surfaces should link or verify those sources without becoming additional complete definitions.

Disposition: address this during the scheduled complete Memory optimization pass rather than changing a recently accepted migration in isolation.

### Phrase-Level Installation Tests

The Core installation closure test checks several exact loader and Memory phrases independently even though source and dogfood loader alignment already has a whole-authored-contract comparison.

This makes wording refinements update a second manual schema without proving more behavior. A stronger direction is to compare installed authored files with canonical source after normalizing generated regions, while retaining focused assertions for generated navigation, preservation, overwrite adjacency, rejection, and other behavior.

Disposition: preserve this as a test-optimization input for the post-migration consistency pass. Do not mix it into the Payload Boundary migration.

### Shared Writing Rules

The [Open Forge Writing Standard](../../crystallized/documents/maintenance/writing.md) now defines shared prose quality, while `docs/dev.md` repeats general voice rules and the [user-facing writing Decision](../../crystallized/decisions/user-facing-writing.md) still reads partly as a parallel current-rule catalogue.

`docs/dev.md` should retain README-specific sequencing and product-presentation constraints while linking to the shared standard. The Decision should preserve the accepted choice and rationale, then link forward to current writing and Markdown sources. Examples in the Writing Standard should remain stable enough that ordinary component changes do not require synchronized example edits.

Disposition: use this finding during the scheduled Decision consolidation and remaining-file optimization passes.

## Lower-Confidence Findings

- The temporary review Directive carries detailed prompts, baseline-session links, branch identity, fallback behavior, and rerun policy in always-loaded context. Its temporary lifecycle may justify that cost, but long-term review behavior should move to an on-demand recipe if it survives migration.
- The Memory model and tag Decisions still contain substantial current-contract summaries. Their useful rationale must be separated from duplicated current meaning during the Decision pass.
- Historical reports need a consistent policy for frozen links and moving current references. This should be decided during the remaining-file review rather than corrected piecemeal.

## Result

The optimization reviewer found structural synchronization and responsibility costs that were not semantic omissions or sentence-quality defects. That is distinct enough to justify a third independent review during the remaining migration.

Optimization findings remain proposals. A finding may be applied directly when it is a small in-scope consolidation with no new product choice. A proposal that changes architecture, public behavior, or the accepted migration boundary requires discussion before implementation.
