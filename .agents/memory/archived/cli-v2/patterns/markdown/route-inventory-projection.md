# Route Inventory Projection

## Boundary

The accepted [Route Inventory
contract](../../../../memory/crystallized/documents/cli/contracts/route-inventory.md)
owns exact topology, route identity, metadata, overwrites, generated
navigation, context projection, detached rebuilding, and invalid-state
semantics. This Pattern owns the reusable one-inventory, many-projections
arrangement. Read document facts through the [Markdown Document
Facts](markdown-document-facts.md) Pattern.

## Shape

```text
selected inventory boundary
  -> authored child discovery
  -> stable document facts
  -> route nodes and relationships
  -> expected derived navigation
  -> current derived comparison
  -> focused consumer projections
```

Build one inventory per invocation. Keep route identity, source path,
Markdown destination, parent relationship, overwrite relationship, and
derived navigation as distinct typed facts. Retain safe facts and positional
findings together so incomplete discovery stays explicit.

Context, discovery, inspection, diagnosis, rebuild, and lifecycle planning
project the same inventory nodes instead of rediscovering topology. Each
projection selects only the fields and relationships its consumer owns. A
detached source uses the same inventory boundary with the exact scope defined
by the linked contract; it never impersonates a rooted workspace.

Ordinary Markdown-reference traversal remains in the separate [Local Reference
Inventory](local-reference-inventory.md). Derived navigation can be compared
or rebuilt, but stale generated bytes never add or remove authored inventory
nodes.

## Review Checks

- One invocation constructs one shared route inventory.
- Typed facts keep identity, representation, relationships, and derived state distinct.
- Consumers project shared nodes instead of reopening private topology variants.
- Safe facts survive alongside explicit incomplete or invalid findings.
- Detached and rooted boundaries cannot be confused.
- Ordinary Markdown traversal remains separate.
- Exact route and projection semantics come only from the linked contract.
