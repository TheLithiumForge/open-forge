## Decision Frame

The council looked for repeated agent jobs still missing after:

- Structured human and JSON results.
- `status`, `find`, `context`, route inspection and cataloguing, references,
  diagnosis, and index maintenance.
- The historical executable Discovery manifest candidate, which the maintainer
  later rejected in favor of manually organized help and documentation.
- Path-only and provenance-rich domain projections.

Any survivor had to remove a repeated multi-call or full-file-read workflow,
retain one clear semantic source, and avoid fuzzy search, persistent hidden state,
generic queries, or duplicated command meaning.

## Independent Perspectives

### Workflow Efficiency

This view proposed stable machine output, explicit multi-target batching, a
structural document outline, context-selection trace, and mutation dry-run. Most
are already accepted cross-cutting behavior or projections of existing
operations. The structural outline remained the clearest possible missing job.

### Framework Semantics

This view identified provenance explanation and live capability introspection as
the only plausible additions. It recommended exposing structure and provenance
through existing resolvers and manifests rather than separate metadata, outline,
navigation, or authority commands.

### Radical Simplifier

This view recommended freezing the top-level command set. It allowed only an
operation-scoped provenance projection if repeated causal debugging proves that
existing context and inspection results are insufficient.

### Automation Contract

This view prioritized a capability manifest, machine-readable command
descriptors, deterministic JSON, structured diagnostics, and consistent source
provenance. These are product guarantees or Gate 3 schema work, not additional
domain commands.

## Historical Reconciliation

The synthesis below predates maintainer feedback. Heading output and existing-
operation provenance are now accepted boundaries, while read-only batching is
deferred until post-implementation evidence exists.

No additional top-level operation is justified now. The council reduced the
remaining ideas to three evidence-gated candidates:

1. A structural outline for one selected Markdown source.
2. Explicit multi-target batching for a read operation.
3. Additional operation-scoped provenance fields or trace views.

Capability descriptors, stable JSON, structured diagnostics, source IDs/paths,
dry-run parity, and completion generation belong in existing cross-cutting
contracts or Gate 3 technical design. They should not create another domain
command.

## Historical Evidence Threshold

These thresholds predate maintainer feedback. The outline and provenance
thresholds now inform conformance evidence for accepted operation-scoped
projections. The batching threshold remains the evidence gate for its deferred
idea.

- An outline requires at least three recurring tasks where an agent reads most
  of a file only to learn headings, section ranges, tags, or basic structure.
- Multi-target batching requires measured process/tool-call overhead across at
  least five explicit targets and a result contract that cannot look partially
  complete after one target fails.
- A provenance projection requires at least three repeated workflows that need
  more than two current operations to explain selection, loading, route, or
  overwrite reasons.
- Any candidate must preserve the same parsed facts and semantic result as its
  domain operation and reduce calls, reads, or output in a fixed comparison.
