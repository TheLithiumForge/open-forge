The split contract migration is complete. The current Interface, Behavior, and
optional Technical Design files are the authoritative Working contracts for
`find`, `index`, `status`, `context`, `route inspect`, `route init`, `route

## Accepted post-baseline updates

The following accepted changes were added after `e0f26fe` and are recorded in the
current split-contract program:

- Global `--view=compact|expanded` defaults to expanded human output. It is a
  no-op under JSON or where an operation has no distinct human view.
- Context provides ordered `paths` and parsed `headings` projections. Find
  reuses headings but keeps its own inventory order and rejects context paths.
- `metadata` means CLI-generated source metadata without authored payload.
  Authored YAML remains `frontmatter`.
- The Queue 06 Find Interface decision retains flat `all` when `--require` is
  omitted and keeps explicit `any` available without grouping or an explicit-mode
  requirement.
- The permanent [Source Universe Filters contract](../../crystallized/documents/cli/contracts/shared/source-universe-filters/interface.md)
  defines reusable operation-specific `--include=<source-reference>` and
  `--exclude=<source-reference>` filters. Find and References explicitly apply
  the contract; unrelated commands reject these flags as unknown. Omitted
  include uses the consuming command's declared default, which for Find and
  References is the normal complete eligible `.agents` Markdown universe;
  omitted exclude subtracts nothing. Includes union, excludes union, and
  exclusion wins overlap.
  Folder-root references (`Loader`, recognized `entrypoint`, or `SKILL.md`)
  expand to their physically contained eligible Markdown subtree, including
  unrouted Markdown. Ordinary references select one logical source, and
  base/overwrite remain one logical source. This is not route, lifecycle, tag,
  or authority inference. Complete coverage is relative to the explicit
  effective universe; no `--limit` or count cap is accepted.
- The accepted Queue 09–10 Index decisions define idempotent repetition for
  `--dry-run` and `--skip-git-check`, assign primary human results to stdout and
  primary human errors to stderr, keep JSON as one structured stdout result with
  separate bounded diagnostics on stderr, and return `attention` for a safely
  established dry run with a non-blocking finding. Current Interface and
  Behavior links record the decisions; they do not reopen migration.

These accepted post-baseline updates do not reopen the completed migration or
introduce permanent requirement IDs.

## Review evidence and lifecycle

Independent migration review, council material, and the Review Queue are
contextual preparation evidence. They did not create the current authority
transition. The maintainer's accepted direction did. Settled review units are
recorded in [`review/queue.md`](review/queue.md); future independent review uses
one fresh Luna review unless the maintainer requests another shape.

The four top-level command-overview Working views are accepted concise
Documents, not Patterns.
Templates remain optional copy-ready starters and receive their final
reconcile/update/remove pass after all commands are defined. No new Decision
record is needed now; the [Decision Agenda](../../working/cli-release/decision-agenda.md) is sufficient
during Gate 2.

The ledger can move or be archived only after its temporary labels are removed,
the final Index staging is resolved, and useful migration rationale remains
available in the appropriate current or historical source. Until then, this
completed-evidence record stays active.
