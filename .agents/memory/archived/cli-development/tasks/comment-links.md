# Comment Links
Comment Links is the issue 21 feature that connects code and docs through path comments. This record keeps its decisions after the working checkpoint was archived. The run receipts, rebase notes and reproduction commands that filled the checkpoint stay in Git and CI history.

The [source-reference contract](../../../crystallized/documents/cli/contracts/shared/source-references/interface.md#comment-links) defines the current grammar, discovery and repair rules. The References, Context, Doctor and Repair contracts, `docs/cli.md`, the Docusaurus CLI page, References help and both CLI Skill copies describe the public behavior.

Original status: implementation complete on PR #27, with the full managed and native suites gated in CI.

## What Was Built

- `@open-forge <path> <text>` at the start of a comment links code and docs. The `@rune` marker is also recognised. Examples use `@open-forge`.
- Plain targets start at the repository root, and `./` or `../` start next to the containing file. Fragments follow the issue 22 rules for headings, line ranges and symbols.
- References lists comment occurrences in both directions and accepts exact code paths. Context checks them during requested link expansion. Doctor reports missing targets and failed fragments.
- Repair changes only the target word and writes an encoded repository-root path. Suggestions rank a Git file rename, a Git heading change, the old section's content in another doc and a unique slug (weak), in that order.
- The 66 audited code-link occurrences across 15 historical docs were fixed. The [fragment record](code-link-fragments.md) keeps that audit.

## Review Decisions

The maintainer selected spec review findings A1 through A6:

- A1 decodes the selected comment path once and reuses the shared path encoder.
- A2 selects comment delimiters by file syntax and allows trailing comments.
- A3 admits native Markdown images only from Markdown files.
- A4 pairs unique changed headings from the target diff before section-content evidence.
- A5 corrects the References source-universe and Repair exact-relink contracts.
- A6 keeps the four suggestion kinds distinct through Repair.

## Lean Version

The maintainer asked to remove everything issue 21 did not need. The lean branch kept the draft commits and removed:

- the legacy ID-anchor findings. An ID-style target is an ordinary missing target.
- the eight archived `.ts.txt` source copies. Their citations use commit-pinned GitHub permalinks at `d9be2d93b`.
- the whole-file content match labelled as a Git rename. A target moved but not yet committed gets no rename suggestion.
- the hand-written discovery skip list. Discovery reuses the Route Inspect workspace file list, which respects `.gitignore`, and keeps the `<auto-generated` and `@generated` header check. The maintainer accepted both the header check and the missing suggestion for uncommitted moves.
- the `@rune` examples in the shipped Skill, `docs/cli.md`, the Docusaurus page and References help.
