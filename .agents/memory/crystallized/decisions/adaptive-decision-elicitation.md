# Adaptive Decision Elicitation

## Context

Open Forge already distinguishes user authority, agent autonomy, routed context, optional Workflows, current documents, Decisions, #Core material, and Memory states.

The missing default was the interaction between sparse natural intent and those mechanisms. Technical users often supply enough design direction themselves. Less technical users may not know which choices matter and should not be expected to invent implementation structure or operate the Framework taxonomy.

A universal questionnaire or mandatory discovery phase would repeat the process overhead Open Forge exists to avoid.

## Decision

The base Framework requires agents to build the best current model from the request and accepted context before consequential work depends on an unsettled choice.

Agents match explanation and planning depth to the request's demonstrated expertise and desired fidelity. They surface only missing decisions that could materially change the outcome, scope, experience, structure, risk, cost, or verification. They recommend coherent defaults, distinguish them from accepted direction, explain meaningful tradeoffs through understandable outcomes, and ask only for judgment the user must supply.

Reversible assumptions may remain visible and #Contextual when work can safely proceed. Settled direction is not reconfirmed, exhaustive specifications are not required, and low-impact preferences do not become gates.

Users express intent naturally. Agents select applicable `routes`, Workflows, Skills, Templates, and durable destinations. When an optional capability materially changes the interaction, the agent explains the useful approach in one natural sentence without requiring Framework vocabulary.

Detailed Vision, Architecture, Planning, Development, Review, and Experience Design methods remain optional. They never form a mandatory lifecycle.

## Rationale

This preserves user authority where contextual judgment matters while reducing the expertise and ceremony required to provide useful direction.

Recommendations are more helpful than unbounded option lists. Outcome-oriented questions let users decide what they uniquely know without outsourcing technical design back to them.

The universal behavior belongs in the loader because it must apply before optional capabilities are selected. Detailed methods remain optional because the shared Framework should not impose a development methodology.

## Alternatives And Tradeoffs

- Native agent competence alone would keep the base smaller but leave proactive elicitation inconsistent across agents and runtimes.
- A required discovery Workflow would improve consistency but impose stages and ceremony even when accepted context is sufficient.
- A universal questionnaire would make coverage visible but increase burden, encourage irrelevant answers, and perform poorly across different subjects and user expertise.
- Automatic inference without visible assumptions would reduce questions but let agent guesses become silent product direction.

The baseline contract adds repeated context cost. Its wording therefore remains compact and defines decision economy rather than a complete elicitation method.

## Consequences

- Natural conversation is sufficient input for ordinary Open Forge use.
- Agents adapt question depth to request completeness and material uncertainty.
- Agents adapt technical detail and planning depth to demonstrated expertise and requested fidelity.
- Technical users are not forced through settled questions.
- Less technical users receive recommendations and understandable decision points.
- Documents and other routed material emerge as warranted outcomes rather than required forms.
- Evaluation must test both consequential decision coverage and unnecessary questioning.
