# Task Acceptance

## Goal

Finalize one complete task after its selected evidence and primary-owner review pass, while keeping integration, remote, release, and continuation effects inside explicit authority.

## Steps

1. Require the selected focused, integration, public, and full evidence for the task profile, plus primary-owner inspection of actual artifacts and any required independent review.
2. Resolve blocking findings through the recorded grouped correction budget. Consume one correction-budget unit for each correction cycle, recheck changed finding IDs and affected evidence, and stop when the maximum is exhausted. Return unresolved material decisions instead of manufacturing acceptance.
3. Update the declared task source with delivered outcome, changed artifacts, evidence, finding disposition, residual risk, and completion state.
4. Create a coherent local commit only when authorized and useful. Do not merge, push, open a pull request, publish, deploy, release, or mutate external systems without exact authorization for that effect and target.
5. Reconcile affected current sources and generated projections through their authorized process.
6. Continue to the next task only when its outcome is already authorized. Start from a fresh baseline and execution capsule rather than silently expanding the accepted task.

## Completion

- The selected evidence passed and no blocking finding remains.
- Findings and correction disposition are explicit.
- Task and durable source state match the delivered result.
- Local commits, integration, external effects, release, and continuation remained inside exact authority.
- Residual risk and the next authorized action are visible.
