# Face catalogue
This page describes the 128 card-face identities generated by `face-design.ts` and drawn by `Face.tsx`.

The catalogue is a compact product of eight shapes, eight marker positions and two fills. Color follows marker position. It is useful for source review, face-sheet inspection and reproducing a particular artwork report. Pair generation and deck order are separate subjects in [Pair identity](pair-identity.md) and [Deck generation](deck-generation.md).

## Decoding a face ID

`FACE_COUNT` is 128. `faceDesign(face)` accepts integer IDs from 0 through 127 and throws `Error('Invalid face.')` for values outside that range or values that are not integers. The function then selects from ordered arrays rather than looking up 128 independently authored drawings.

For an ID `f`, the shape index is `f % 8`. The marker index is `floor(f / 8) % 8`. IDs below 64 are solid; IDs from 64 onward are outlined. The same marker index selects both the marker name and its palette color. These operations define the catalogue's ordering and generated names.

The inverse relationship is `f = shapeIndex + 8 * markerIndex + 64 * fillIndex`, where fill index 0 is solid and 1 is outline. This is a convenient way to locate a comparison in the sheet. It describes the existing arithmetic; it is not an additional exchange format or a new public identifier.

## Shapes in order

| Index | Shape | Element and geometry in the 100-unit view box |
| --- | --- | --- |
| 0 | circle | Circle centered at `(50, 50)`, radius 25 |
| 1 | square | Rectangle at `(25, 25)`, width and height 50 |
| 2 | triangle | Vertices `(50,25)`, `(75,75)`, `(25,75)` |
| 3 | diamond | Vertices at top, right, bottom and left of the central box |
| 4 | star | Ten-point path alternating outer and inner vertices |
| 5 | hexagon | Flat top and bottom, left and right vertices at y=50 |
| 6 | plus | Twelve-corner orthogonal path with a 16-unit central bar |
| 7 | chevron | Six-corner path with a top notch and a lower point |

All shapes occupy the central `25..75` coordinate range on each axis. That common box is a layout fact, not a claim that the filled areas are equal. A circle and a plus necessarily cover different amounts of the surface. Their silhouette and interior negative space are part of the distinction.

The star path is `M50 25 57 42 75 43 62 56 66 75 50 65 34 75 38 56 25 43 43 42Z`. Its upper arm coordinates are deliberately explicit rather than generated by a polygon library. The plus path is `M42 25H58V42H75V58H58V75H42V58H25V42H42Z`. The chevron path is `M25 25 50 46 75 25V53L50 75 25 53Z`.

These exact paths explain some easy naming mistakes. The chevron is a filled polygon with a notch, not a stroked down-arrow glyph. The plus has square interior turns in its path, though outline rendering uses rounded joins. The diamond is a separate central shape from the decorative diamond on a closed card's back.

## Marker positions and colors

Marker centers lie 40 units from `(50,50)`. Axis-aligned directions use an offset of 40 on one axis. Diagonals use `DIAGONAL_OFFSET = 40 / Math.SQRT2`, approximately 28.284271. Using 40 on both diagonal axes would put those markers farther from the center than the axis-aligned ones.

| --- | --- | --- | --- | --- |
| 0 | top | `(50,10)` | cyan | `#63E7FF` |
| 1 | top-right | `(78.284,21.716)` | magenta | `#FF71D6` |
| 2 | right | `(90,50)` | green | `#8BEA7D` |
| 3 | bottom-right | `(78.284,78.284)` | yellow | `#FFE082` |
| 4 | bottom | `(50,90)` | orange | `#FFB064` |
| 5 | bottom-left | `(21.716,78.284)` | violet | `#B49AFF` |
| 6 | left | `(10,50)` | rose | `#FF8296` |
| 7 | top-left | `(21.716,21.716)` | ice | `#D9F3FF` |

Each marker is a circle with radius 5 and a 3-unit stroke in `var(--face)`. The circle is drawn after the main shape, so its surround separates it from the shape where their extents approach. The surround is especially relevant to square corners at diagonal positions. A screenshot of one top-marker circle is insufficient evidence for every marker's separation.

The marker's outer radius, including half its stroke, is 6.5 units. At an axis-aligned center 10 units from the view-box edge, this leaves 3.5 units between that outer stroke and the edge. The coordinate system therefore provides breathing room without needing card-specific SVG padding. The card's border is outside the SVG drawing area.

## Fill and stroke behavior

`Face.tsx` puts the central shape in a group. For solid faces, the group fill is the face color and its stroke width is zero. For outline faces, fill is `none`, stroke is the face color, and stroke width is 5. Both cases set the stroke color, but the zero width means it contributes no solid-face outline.

The group uses `strokeLinejoin="round"`. This affects outline corners, including the star and plus. The marker is outside the group and keeps its own fill and face-background stroke regardless of the central fill mode. Switching from solid to outline does not turn the marker into a hollow circle.

There is no `vector-effect="non-scaling-stroke"`. The five-unit shape stroke and three-unit marker surround scale with the SVG. At a 44px card's approximately 40px inner area, they correspond to about 2px and 1.2px respectively. At the maximum card size they are proportionally wider. [Card artwork](card-artwork.md) explains the surrounding border and check geometry.

## Catalogue ranges

| Solid range | Outline range | Marker and color |
| --- | --- | --- |
| 0–7 | 64–71 | top, cyan |
| 8–15 | 72–79 | top-right, magenta |
| 16–23 | 80–87 | right, green |
| 24–31 | 88–95 | bottom-right, yellow |
| 32–39 | 96–103 | bottom, orange |
| 40–47 | 104–111 | bottom-left, violet |
| 48–55 | 112–119 | left, rose |
| 56–63 | 120–127 | top-left, ice |

Within each range the shape order remains circle, square, triangle, diamond, star, hexagon, plus, chevron. Moving eight IDs changes the marker and color while preserving shape and fill until the range boundary. Moving 64 IDs from a solid face changes only its fill treatment.

Some useful spot checks are face 0, `cyan solid circle, marker top`; face 9, `magenta solid square, marker top-right`; face 64, `cyan outline circle, marker top`; face 73, `magenta outline square, marker top-right`; and face 127, `ice outline chevron, marker top-left`. These samples cover the basic indexing, a diagonal corner and the upper valid limit.

The generated label follows lowercase color, fill and shape names, then `, marker ` and the position name. `Face.tsx` itself is hidden from the accessibility tree; the card's name incorporates this label when the face is visible. Labels are therefore diagnostic and accessible descriptions, while numeric IDs remain the game's pair data.

## Which faces appear in a game

`generateBoard` begins with pairs of consecutive face IDs, from zero through half the card count minus one, and shuffles the positions. A 4x4 board contains eight identities; a 16x16 board contains all 128. Intermediate boards exercise progressively larger prefixes of the catalogue, rather than sampling an arbitrary subset of 128 identities.

This matters for visual testing. A small game cannot expose every outlined face, even if played to completion. The first outline identity is 64, so the catalogue sheet and largest board cover combinations absent from the default board. A report that the default game looks correct does not address diagonal outlined squares.

The art sheet sidesteps deck order by rendering each ID once in catalogue order. Its eight-column layout makes each marker/color group a row, followed by the next group. The lower half repeats the shape and marker combinations in outline form. The labels provide IDs even when grayscale removes the palette names' visual usefulness.

## What the tests establish

`face-design.test.ts` builds identity tuples from shape, center and outline and checks that all 128 are distinct. It checks the diagonal distance, rejects representative invalid inputs, and compares every ID with independent ordered shape, marker, color, name and center tables. It also has a small reviewed snapshot comparison for IDs 0, 64 and 9.

`tests/art.e2e.test.ts` renders the real 44px cards. It captures a color sheet and a grayscale sheet, then recolors the geometry to a common pale value and compares thresholded raster masks. The unique-mask assertion verifies that every rendered geometry remains distinct at that size. This is stronger than uniqueness of numeric tuples, but it is still not a substitute for human recognition of similar forms.

The same test file checks the marker view box, radius, stroke width and computed surround color, plus fill and stroke palette use for every face. `tests/matched-mark.e2e.test.ts` adds the state mark to the complete largest board and checks that it covers neither marker nor shape. These tests answer different questions: identity arithmetic, raster distinction, palette placement and overlay clearance.

When a face changes, the most informative review names the affected ID and combination and compares the neighboring shape, its other fill, and nearby marker positions. [Visual review checklist](visual-review-checklist.md) links this work to the layout and contrast checks without treating a large, isolated SVG preview as sufficient evidence.
