# Vision

Vision clarifies what should exist, why it matters, what belongs in the first useful version, and what routed context should guide later work.

## Mode

iterative

## Goal

- outcome: a vision with core value, a first-useful-version boundary, explicit non-goals, growth directions, and a reviewed supporting-route bundle
- acceptance: the requested candidate analysis is delivered with its status explicit, or the user accepts, revises, defers, or rejects the direction
- stop: requested analysis delivered, explicit direction decision made, required context unavailable, or user input needed for a value choice

## Required Routes

Read every route below before Step 1. A route that cannot be read is a blocker to report, not a step to skip.

- `.agents/skills/vision/SKILL.md` - vision shaping, first-useful-version boundary, fit, risk, and growth-direction capability

## Constraints

- Treat the vision as candidate direction until the user accepts it.
- Do not promote strategic direction to #CurrentTruth without user confirmation.
- Prefer concise questions and concrete options over broad strategy prose.
- Separate user-stated needs, observed signals, and inferred consequences; obtain user accord before promoting inferred material or creating normative #Core guidance, patterns, or directives.
- Create only material that will guide recurring work; "none warranted" is valid and preferable to ceremonial files.

## Steps

1. Clarify the problem, audience, desired outcome, constraints, non-goals, decision owner, and whether the user wants candidate analysis, routed artifacts, or both.
2. Elucidate user-stated needs, observed signals, inferred consequences, unresolved assumptions, important terminology, principles, recurring preferred approaches, and validation signals without conflating their provenance.
3. Identify the core value that must exist for the direction to matter.
4. Shape the first useful version and separate explicit non-goals and later growth directions.
5. Check fit, risks, evidence, validation signals, and assumptions that could invalidate the direction.
6. Derive a candidate support bundle and state why each item is or is not warranted: directives only for genuine hard requirements; patterns for recurring product, experience, process, or artifact structures; guidance for evidence-backed or user-recognized preferred approaches; workspace routes for important sources; and memory records for accepted direction, rationale, terminology, assumptions, and future candidates.
7. Label every candidate user-stated, observed, or inferred with confidence and source. Ask for user accord before promoting #Core or #CurrentTruth material.
8. On accord, create or update the minimum routed artifacts without duplicating owners and run `open-forge index` plus `open-forge doctor` when available. Without accord, preserve useful candidates in emerging memory when authorized, or report their proposed routes without promotion.
9. When the user requested a decision or the direction may become project truth, ask them to accept, revise, defer, or reject it; otherwise present it explicitly as a candidate with the next decision or validation need.

## Loop

Repeat steps 1 through 7 when the user changes the audience, core value, first-useful-version boundary, constraints, risks, or validation path. Repeat step 8 after artifact revisions. Stop per the Goal's stop condition.

## Outputs

- accepted or candidate vision summary
- first-useful-version boundary and explicit non-goals
- future directions
- risks, assumptions, and validation signals
- candidate support bundle with provenance, confidence, accord status, and explicit none-warranted results
- accepted directives, patterns, guidance, workspace routes, and memory, or emerging-memory/proposed-route fallback
- open questions

## Completion

- [ ] status is explicit: candidate analysis delivered, accepted, revised, deferred, or rejected
- [ ] every supporting candidate states provenance and was promoted only with user accord
- [ ] warranted accepted directives, patterns, guidance, workspace truth, and memory were routed and rechecked, useful unaccepted candidates stayed emerging, or no material was warranted
- [ ] handoff written when continuation would benefit from a static resume note
- [ ] final response or handoff names this workflow
