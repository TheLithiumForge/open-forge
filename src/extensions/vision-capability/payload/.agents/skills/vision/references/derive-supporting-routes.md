# Derive Supporting Vision Routes

Use this after the problem, audience, core value, first useful version, and risks are clear enough to expose recurring project context.

- Propose directives only for genuine hard requirements. Choose the root directive route only for workspace-wide requirements; otherwise propose a positively described child directive route before writing one substantive level-2 `## Axioms` section. Do not add an `Applies To` gate.
- Propose patterns for recurring product, experience, process, vocabulary, or artifact structures that should be inspectable.
- Propose guidance for evidence-backed or user-recognized preferred approaches that still require contextual judgment.
- Propose workspace routes for important product sources, research, assets, plans, environments, or decision owners.
- Route accepted direction and rationale to established memory owners; keep future ideas, unresolved assumptions, and unaccepted deductions emerging.

Label each candidate as user-stated, observed, or inferred. State its evidence, confidence, expected consumer, and proposed destination. Ask for user accord before creating or promoting normative #Core or #CurrentTruth material. Without accord, keep useful material emerging when authorized, return a ready-to-route proposal, or explicitly state that no supporting material is warranted.
