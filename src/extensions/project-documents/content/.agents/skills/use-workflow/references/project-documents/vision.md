# Vision

## Goal

Produce a candidate or accepted Vision that makes the subject's purpose, core value, first useful version, boundaries, and success clear. Use existing sources when they already own the answer; a new document is optional.

[Document Templates](../../../../templates/documents/_documents.md) provide optional starting files. Use existing defining sources when they already answer the question; the Documents category is a convention, not a required destination.

## Steps

1. **Start from the request.** Load applicable project scopes and current direction. Build the best current understanding from what is already known. Separate accepted direction from assumptions and recommendations.
2. **Resolve only consequential choices.** Identify unanswered questions that could change the problem, audience, outcome, constraints, first useful version, non-goals, or decision authority. Unless deeper analysis is requested, begin with the understood outcome, one recommendation, and at most one important open choice.
3. **Define the promise.** State who benefits, what becomes possible, and why it matters. Identify the core value that the first useful version must deliver. Keep future possibilities from expanding the initial commitment.
4. **Challenge the direction.** Check audience fit, constraints, material risks, and the cheapest credible validation signals. Separate observations from proposed checks. Evidence supports a claim; acceptance establishes the direction that may guide work.
5. **Refine to the needed depth.** Repeat only while unresolved questions could change the direction materially. Do not require a complete implementation specification to settle a Vision.
6. **Preserve the result.** Present the Vision at the requested level of detail and state whether it is proposed, accepted, revised, deferred, or rejected. When authorized, update its defining source. Save useful unresolved ideas in an existing candidate route rather than presenting them as current commitments.

## Completion

- The problem, audience, core value, first useful version, non-goals, growth direction, and observable success are clear.
- Material assumptions, risks, validation limits, and unresolved choices remain visible.
- Accepted direction is reflected in its defining source when a durable update is needed and authorized. Proposed direction remains visibly proposed.
