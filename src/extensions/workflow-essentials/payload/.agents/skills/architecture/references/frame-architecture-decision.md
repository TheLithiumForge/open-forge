# Frame Architecture Decision

## Use When

Use when an architecture choice is accepted or needs to be prepared for user confirmation.

## Capability

- State the context, decision, rationale, consequences, and rejected options when useful.
- Keep behavior, patterns, workspace routes, and implementation rules in their owning #Core or #Memory routes.
- Mark uncertainty and follow-up work separately from accepted rationale.
- Suggest the right decision or document route without creating parallel truth.

## Expected Result

Architecture rationale is durable and discoverable, while operational behavior remains in the route that owns it.
