# Contract Skeleton

## Use When

Use when tests or implementation need a stable shape before behavior is filled in.

## Capability

- Define public contracts, inputs, outputs, states, errors, and ownership.
- Create minimal skeletons only when they clarify tests or integration.
- Avoid filling implementation details before expected behavior is clear.
- Keep skeletons aligned with local naming, placement, and pattern routes.

## Expected Result

Tests and implementation can target a clear shape instead of a vague intention.
