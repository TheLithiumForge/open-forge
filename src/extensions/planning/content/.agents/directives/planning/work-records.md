# Work Record Relationships

## Instructions

- Use the project's declared task source and established record conventions. The [Work Records Pattern](../../patterns/work-records.md) is a default only where no suitable structure exists. Its content responsibilities do not impose a mandatory schema or headings. Small work may need only the current conversation.
- Keep the Task's outcome, planned sequence and current state together until one needs separate scope, lifetime or coordination. A Backlog lists work awaiting selection and links to a Task once one exists. A listed idea is not automatically accepted work.
- The Task defines the outcome and completion criteria. A separate Plan defines the sequence only when separated, and the Task then links to it. A Checkpoint holds additional live continuation state and links to the Task and Plan instead of repeating specifications or finished history. A Handoff required by an actual transfer seals that boundary and does not replace live state.
- An Idea preserves a possibility, Analysis preserves evidence and reasoning, and a Decision preserves an accepted choice and rationale. None is a mandatory predecessor to a Task. A small accepted choice may remain in an existing source when no separate record helps.
- Keep current project knowledge in its defining local document or external system. Task records carry only context needed to execute. Each changing fact has one defining source. Use external task systems for facts assigned to them. Local records may add context those systems do not maintain. Do not create a second board, status catalogue or sequence by copying.
- At completion, report the delivered outcome, decisive evidence, limitations and remaining work. Move still-current knowledge to its defining sources before retaining or archiving the working record under workspace rules. Status records events and grants no acceptance, new scope, integration or publication authority.

The [Planning workflow](../../skills/use-workflow/references/planning/planning.md) supplies the procedure. [Planning Templates](../../templates/planning/_planning.md) are optional starting files.
