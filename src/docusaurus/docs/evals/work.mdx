# Work

The evals hold a pool of tasks and the ways of doing them. A task is one change to the existing app. A work packet hands several tasks over together, and its work mode says how. Every task and packet runs on every [scenario](scenarios.mdx), the project contexts from Code only to Open Forge, so the comparisons can separate what the context changes from what the way of working changes.

## Terms

| Term | Meaning |
| --- | --- |
| Layer | How much the agent gets before it starts: an idea, a short brief, a full spec or an existing app. [Starting points](starting-points.mdx) describes each one. |
| Task | One change request from the pool, with its own checks |
| Work packet | Tasks handed over together, with all of their checks |
| Work mode | How a packet is done |
| Scenario | The project context the agent starts with |
| Implementer | The model and its reasoning level, and in orchestrated work, its subagents' model |
| Run | One task or packet, in one scenario and work mode, by one implementer |
| Stage | Work, then checks, then judges, each run whenever you choose, as [Run](run.md#run-a-batch) describes |

## Work modes

| Work mode | What the agent gets |
| --- | --- |
| Whole packet | One agent, one chat, every task in one request |
| Task by task | A new agent per task, each starting from the previous task's result |
| Orchestrated | One orchestrator for the packet, handing each task to a subagent |

Task by task runs each task as a batch of its own, in order, and adds their tokens up for the packet. Orchestrated work runs Sol leading Sol subagents and Sol leading Luna subagents, and the orchestrator gets one registered line after the request that tells it to delegate each task. The Results page filters by work mode, and its Work packets table puts each scenario's work modes side by side.

Earlier batches ran one task alone from a clean start. They show as One task.

## What the comparisons answer

- Scenarios within one work mode: what does the project context change?
- Work modes within one scenario: what does handing a packet over whole, task by task or to an orchestrator cost, and does it change the result?
- Implementers within orchestrated work: does a smaller subagent model save tokens?

Two runs per cell are still a first read, not a measured difference. Small fixes like these reach nearly full coverage in every scenario, so the first differences show in tokens and time.

## Layer 3

Layer 3 fits the same work modes. The full build in one request is a whole packet, and the three milestones, a playable game, then visuals, then saving and sharing, are task by task.
