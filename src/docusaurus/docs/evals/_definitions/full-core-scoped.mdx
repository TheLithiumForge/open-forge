The project gets the same install as Full Core, with the spec routed by scope. Only the overview loads at startup. The other documents sit in six scope folders: Gameplay, Controls and input, Visuals, Sound, Persistence and sharing, and Technology. Each folder's entrypoint says what the scope covers, so an agent opens a scope only when its task needs it. The acceptance examples stay at the top of `docs/` and also load on demand.

The document text is the same as in Full Core. Only the links between documents change, so they point into the scope folders.

This is how Open Forge is meant to be used: context arrives when a task needs it. Full Core and the other presets load nearly the whole spec up front and stand in for Open Forge used without scopes. Full Core, scoped is compared on a full spec and on an existing app, where the spec is complete too.
