`l4-f2-tournament`, "Tournament mode", is a large feature case that tests documentation at a size no agent can read in one go. The request asks for a knockout tournament for 4 or 8 players on one device, and gives every label a person sees, so Code only can build it too.

The project brings about 380,000 tokens of documents, with 30 project rules planted one per document. Most of them never mention tournaments, so searching for the feature misses them. Twelve core checks need only the request. Thirty rule checks need the documents, and their coverage is the case's main measure.

How rules reach the agent depends on the setup. Plain docs and Organized docs leave them inside their pages, so an agent has to find and read those pages. [Full Core, proper](../scenarios.mdx#full-core-proper) and [Minimal, proper](../scenarios.mdx#minimal-proper) move about 340 rule sentences into Directives, including every graded rule, as chosen by a reader that couldn't see which ones are graded. That difference is what using Open Forge properly means, so the case partly tests whether agents find rules and partly whether they obey what they're handed.
